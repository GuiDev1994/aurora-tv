# Phase B Soft Recovery — Aurora v1.1.5

**Date:** 2026-07-20  
**Status:** Implementation (local test)  
**Branch:** `feature/v1.1.5-soft-recovery` (do not merge until C5 smoke)

## Goal

Reduce residual / growing 4K input-video delay on LG C5 without Flush+IDR loops. When decode backlog pressure is sustained, temporarily lower host bitrate so the Starfish path can catch up.

## Behavior

1. Opt-in setting **Soft recovery (4K)** (`soft_recovery`), default **on** for webOS testing.
2. Gate: stream pixel count ≥ 3840×2160.
3. Sample every stats window (even if overlay hidden):
   - Starfish `RQ` via `SS4S_PlayerGetVideoRenderQueueLength` when available
   - Decoder latency via `SS4S_PlayerGetVideoLatency`
   - `receivedFps` vs `decodedFps` deficit
4. Pressure if any of:
   - `RQ >= 2`
   - `receivedFps >= 0.9×target` and `decodedFps < 0.85×target`
   - `avgDecoderLatency > 80 ms` (when available)
5. Sustained ≥ **3 s** → request ABR drop to **75%** of current bitrate, hold **15 s**, cooldown **20 s** between drops.
6. No Flush+IDR watchdog. `pauseAtDecodeTime` stays independent.

## Files

- Settings + Video pane checkbox
- `adaptive_bitrate_request_drop` (async; applied on ABR thread)
- ABR starts when user ABR **or** soft recovery is enabled (`recovery_only` when only soft recovery)
- `session_video.c` sampling + state machine
